## 已确认的交互基线

| 编号 | 结论 |
| --- | --- |
| U-01 | 一个项目 Workspace 组织一个项目的任务、终端和相关记录 |
| U-02 | 任务页保留列表，并增加看板切换；两个视图共享同一批任务和完整详情 |
| U-03 | 主看板使用待办、进行中、待验收、已完成四列；保留待规划、受阻和已取消状态 |
| U-04 | 拖入进行中表达执行意图；缺少配置先补配置；同列拖拽调整展示顺序 |
| U-05 | 交付后由用户验收；退回修改继续使用同一张任务卡片，并保留执行历史 |
| U-06 | 任务进度和执行状态分别显示；拖回待办涉及中断时明确确认复合动作 |
| U-07 | Agent 管理保留独立页面，Task 面板、任务页、新建任务均有入口；返回时保留草稿 |

以下技术决定是对上述交互的具体化，实施时按本文档验证，不把浏览器演示代码
当作 Runtime 业务逻辑。

## 主要技术决定

1. **项目 ID 复用 `WorkspaceId`。** 现有 Task、默认 Agent、WorkspaceSnapshot 已经
   使用该稳定身份。新增 ProjectCatalog 保存项目元数据，不整体重编号历史数据。
2. **项目可以没有打开的终端。** 持久项目列表与 `WorkspaceCollection` 的实时
   Surface 集合分开；Task 内项目选择不改外层 Workspace 选择或普通新标签的归属。
3. **Runtime 保持 SQLite 唯一写入者。** 看板、列表和详情使用同一套投影与命令；
   界面拖拽不直接更新业务字段或操作 Git/Provider。
4. **拖拽是显式用户命令。** 创建 Run、停止后移动、返工、验收分别有可恢复的事务或
   操作记录；成功接收命令与实际执行完成分开反馈。
5. **增加摘要分页。** 当前查询最多返回 512 个完整 Task 投影；新看板和列表使用
   有界摘要页、完整计数和按需详情，避免截断后看起来像任务消失。
6. **保留已有 Agent 快照规则。** Agent 的修改和归档不会追溯改写已固定的 Task
   ExecutionContext；更新已有 Task 配置仍需显式操作。

## 与现有设计的关系

本方案扩展 [Task 产品规范](../task-driven-terminal/product-interaction-spec.md)、
[Task 架构决策](../task-driven-terminal/architecture-decision-register.md)及
[自定义 Agent 实现](../custom-agents/implementation.md)。原 M0–M8 的完成记录不变。

| 原有契约 | 本方案如何衔接 |
| --- | --- |
| Task 是持久聚合，Run 是一次执行 | 保持；看板卡片始终使用 Task ID |
| 产品状态由显式命令改变 | 保持；拖拽携带用户请求的状态及执行意图，Run 退出不推断交付 |
| Stop 是无确认的语义 Esc | 原 Stop 按钮保持；“停止并移到待办”作为新增复合动作另行确认 |
| Done 触发已有终端关闭流程 | 保持；不自动清理 Worktree 或删除历史 |
| 普通关闭动作不能关闭任务专属 Surface | 保持；Task 内关闭项目视图不操作 Surface，窗口退出继续沿用 UI 脱离语义 |
| Task 执行配置固定及显式修订 | 保持，包括 Agent 归档后旧配置的继续使用与历史重试 |
| Task 与 Summary/History 分属不同记录链 | 保持；项目导航不会把 Task 对话再复制进 Summary |
| Delete 经过恢复与交付检查，留下最小 tombstone | 保持；真实删除不提供浏览器演示中的假撤销 |

本目录明确新增的用户意图包括：看板启动、带修改意见的返工、停止后移动、仅重新
打开到待办。它们通过新能力协商提供；旧客户端既有 RPC 的含义保持兼容。

## 首版范围

- Task 面板内的项目目录绑定、项目库、打开/关闭视图、归档/恢复与项目默认 Agent。
- 当前/全部项目范围、搜索与状态筛选、列表/看板切换、完整任务详情。
- 四列看板、受阻分组、待规划/已取消入口、同列顺序及合法跨列动作。
- 原 Task 的保存、保存并运行、执行记录、消息队列、Run 详情、停止、关闭、
  取消、验收、重新打开、重试、派生、Worktree 交付清理和删除入口。
- 原 Agent 的创建、编辑、复制、预览、版本冲突、归档/恢复与默认设置。
- 重连、跨窗口状态一致、草稿保留、旧数据迁移及项目视图关闭回归。

多仓库项目、自定义工作流列、跨项目拖拽迁移任务、团队权限、其他 Provider、
Skills/MCP 扩展沿用后续范围，不随本次项目看板接入而开放。
