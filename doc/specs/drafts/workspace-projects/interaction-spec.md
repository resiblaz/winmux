# 交互规范

状态：按 2026-09-07 的追加要求修正：保留原左侧 Workspace，项目管理只在 Task 面板中。
页面中的“项目”指持久化的项目 Workspace；“视图”指某个窗口当前打开的页面。

## 1. 页面结构

```text
应用窗口
├─ 原有 Workspace 侧边栏：工作区列表、信息、折叠、切换和关闭
└─ 当前 Workspace 内容区
   ├─ Task 面板
   │  ├─ 项目选择 · 任务 · 项目管理 · 项目库 · 新建项目 · Agent 管理
   │  ├─ 当前项目 / 全部项目 · 搜索 · 状态筛选
   │  ├─ 列表 / 看板
   │  └─ 同一个完整任务详情与新建草稿
   ├─ 终端
   │  ├─ 普通终端
   │  └─ 已打开的任务专属终端
   └─ 结论：沿用当前 Workspace 的 Summary/History 来源
```

Task 的交付结果、消息和 Run 详情保留在任务详情中。结论入口继续使用现有
Summary/History；未来需要结果总览时，以 Task ID 链接任务结果，避免重复存储。

### 1.1 保留原任务界面

| 内容 | 列表视图 | 看板视图 |
| --- | --- | --- |
| 任务集合、范围、筛选 | 原列表结构 | 同一查询结果按状态分列 |
| 选中任务 | 列表旁显示完整详情 | 点击卡片进入完整详情，可返回看板 |
| 执行、消息、验收、Run 历史 | 复用现有详情控件 | 使用同一个控件和选中 Task ID |
| 管理 Agent | 页面和草稿入口 | 相同入口 |
| Worktree 清理、删除及恢复错误 | 原有生命周期入口 | 进入相同详情流程 |

现有用户升级后的初始任务视图为列表。每个项目记住上次选择；切换视图保留范围、
搜索、状态筛选、选中任务、详情草稿和可恢复的滚动锚点。切换本身不执行任务。

列表继续支持现有更新时间顺序；看板的手动顺序是独立展示偏好，不改 TaskPriority
或 Runtime 调度优先级。

## 2. 项目创建、打开与目录

### 2.1 打开 / 新建项目

1. 从 Task 面板顶部选择项目或进入项目库；“新建项目…”打开目录选择器。
2. 选择目录后校验实际目录身份；名称默认取目录名，可编辑。
3. 同一目录已有项目时优先打开已有项目。历史数据中存在多个独立 ID 时列出供选择，
   不自动合并；不同目录允许同名项目。
4. 选择默认 Agent，可留空使用已有的“本次自定义”配置流程。
5. 保存成功后打开任务页，普通终端按用户操作或已保存布局恢复。

Git 项目默认提供 Task 专属 Worktree；普通目录提供 Direct。使用现有目录校验
策略及错误信息，不因文件选择器返回一个路径就跳过 Runtime 验证。

项目根目录与某个终端当前的 `cwd` 分开。终端 `cd`、切换 Surface 或切换 Git 分支
不会偷偷更换项目根目录。新建任务继承项目根；已执行任务继续使用固定执行上下文。

### 2.2 项目设置

保存名称、项目说明和目录绑定；默认 Agent 使用现有默认设置命令。项目说明在
新建 Task 时固定为项目背景快照，修改说明不追溯改变旧 Task。

更换路径必须验证目录身份并显示对新任务的作用范围。已有冻结执行上下文的任务
不改写根目录；跨仓库或执行模式变化走原来的派生任务流程。首版项目库不提供
自动合并项目或批量搬迁 Task 的操作。

### 2.3 关闭、移出与归档

| 操作 | 用户可见结果 | 执行与数据结果 |
| --- | --- | --- |
| 切换项目 | 打开另一项目的任务页或上次页面 | 原项目 Run 继续；草稿保留 |
| 关闭 Task 内项目视图 | 选中另一项目；没有其他项目时显示项目库 | 仅更新 Task 内导航，外层 Workspace、普通终端、任务 Surface 和 Run 保留 |
| 归档项目 | 项目进入项目库的已归档列表 | 不删除任务和历史；禁止新建、启动及自动跟进 |
| 恢复项目 | 恢复到可打开列表 | 不自动创建 Run，不恢复已取消的执行请求 |
| 关闭窗口 | 窗口正常退出 | 沿用现有 UI detach 与 Runtime 后台运行规则 |

归档要求没有活动/排队 Run、未完成生命周期操作或可自动执行的待处理工作。
存在这些工作时显示具体任务和处理入口，不能将归档实现为隐式批量 Stop/Cancel。
已归档项目仍可查看历史及显式执行已有清理/删除流程。

所有任务完成也不自动归档项目；项目仍是可继续开展工作的长期入口。

Task 面板打开时，即使最后一个终端关闭仍可显示项目任务；关闭 Task 内最后一个项目
视图后显示项目库。外层工作区与终端的关闭、选择和快捷键沿用原规则，保留已有关闭修复。

## 3. 看板与卡片

### 3.1 状态映射

| TaskStatus | 展示位置 | 特殊说明 |
| --- | --- | --- |
| Backlog | 待规划入口 | 加入待办后再安排执行 |
| Todo | 待办列 | 未开始，或执行失败/停止后等待处理 |
| InProgress | 进行中列 | 卡片另行显示排队、准备、运行、等待输入等执行状态 |
| Blocked | 进行中列的“受阻”分组，靠前展示 | 保留真实 Blocked 值及原因；不是改成 InProgress |
| InReview | 待验收列 | 有交付；如执行尚在收尾，明确显示并禁用验收完成 |
| Done | 已完成列 | 用户确认完成；终端关闭失败作为恢复提示保留 |
| Cancelled | 已取消入口 | 记录保留，可显式重新打开 |

受阻分组内拖动只排序。恢复执行使用卡片动作/状态菜单，不通过在同一列移动位置
来猜测用户是否希望启动。

### 3.2 卡片信息

默认显示 Task 短 ID、标题、优先级、Agent 名称、产品状态对应分组，以及一个有
明确文字的执行/关注标记。全部项目范围增加项目名；点击项目名可定位所属项目。

执行标记区分：未执行、已排队、准备中、等待目录、运行中、等待输入、停止中、
已交付、失败/中断、终端恢复异常。仅依据结构化投影；不知道进度时不用虚构百分比。
卡片上的 Agent 是任务已固定的配置或当次 Run 快照，可与管理页当前名称/版本不同。

### 3.3 拖拽状态表

卡片菜单、详情状态菜单和拖拽进入同一套操作解析。下表是新增看板命令的完整入口
契约；其余不在表内的跨列请求拒绝并解释。

| 起点 → 终点 | 条件与动作 | 成功后的反馈 |
| --- | --- | --- |
| 同状态/分组内排序 | 当前项目范围；提交邻接锚点与列版本 | 顺序已保存，不启动执行 |
| Backlog → Todo | 只改变计划状态 | 加入待办，可撤销 |
| Todo → Backlog | 无活动执行；只调整计划 | 移入待规划，可撤销 |
| Todo → InProgress | 使用 Task 固定配置；缺配置先补齐；原子提交用户状态请求和一个 Queued Run | “已排队”，不声称 Provider 已运行 |
| Blocked → InProgress | 显式恢复，允许补充上下文；一个新 Run | 继续执行，保留受阻记录 |
| InReview → InProgress | 填写修改意见；原子保存并领取跟进消息、创建新 Run | 同一卡片的新一轮执行 |
| InProgress → Todo | 无活动 Run 时仅移动并保持 hold；有活动/排队工作时确认“停止并移到待办” | 等停止结果后落位；已有产出保留 |
| InProgress → Blocked | 填受阻原因；存在执行时确认停止并标记受阻 | 显示受阻及原因 |
| Blocked → Todo | 无活动执行；保留原因历史及 hold | 等待重新安排 |
| InProgress → InReview | 用户手动提交时要求无活动执行并填写交付说明；Agent 交付走独立受限命令 | 等待用户验收 |
| InReview → Done | 无活动 Run、未领取消息、自动重试或冲突 intent；调用原验收关闭流程 | 完成；如关闭资源未结束，显示收尾提示 |
| Done / Cancelled → Todo | 明确重新打开；只恢复待办，不创建 Run；保留 manual hold 到显式执行 | 等待执行 |
| 任一允许取消的非终态 → Cancelled | 调用原 Cancel 流程；活动执行时展示影响与确认 | 完成取消后移入已取消，数据保留 |

运行中的 Task 从任意入口都不能直接标 Done。直接从 Todo 拖到 Done、从 Done
拖到 InProgress 等非法跳转不会被 UI 改成多个隐含业务操作。

原“停止执行”按钮仍无确认、立即请求语义 Esc；上表确认的是“停止并改变任务
状态”的复合意图。停止超时沿用五秒提示和再次 Esc，不自动升级为杀进程。

### 3.4 拖拽反馈和排序

- 起拖后显示落点预览；无效落点给出原因。取消拖拽不产生命令。
- 落下后显示待提交/处理中标记；收到提交结果才将其视为业务状态。
- 同一任务的未决操作完成前禁用重复提交；不冻结其他任务卡片。
- 版本冲突刷新该任务或受影响列，保留用户的文字输入，不自动覆盖远端状态。
- 看板排序按项目和列保存。全部项目视图允许合法状态操作，手动排序需切回当前
  项目；跨项目放置不修改所属项目。
- 有筛选或分页时使用目标 Task ID 作为前/后锚点，不用屏幕索引重排整个列表。
- 移动后的卡片被筛选隐藏时提示其新位置，提供“查看任务”；不可表现为数据删除。

排序及纯计划状态调整可在版本仍匹配时撤销。Start、Stop、Cancel、Done 的资源
操作不能用前端恢复数组伪撤销；Delete 继续走原破坏性确认和 tombstone 契约。

## 4. 完整任务详情

保留目标与背景、逐项验收条件、任务属性、当前执行、待处理消息、历史 Run、
工具调用/结果、失败与恢复信息、Git checkpoint、执行配置及其版本来源。

保留以下操作及原有权限/状态限制：

| 操作组 | 入口 |
| --- | --- |
| 创建 | 取消、保存到待办、保存并运行 |
| 执行 | 交给 Agent、打开终端、停止、关闭 Task 终端、重试、继续修改 |
| 配置 | 选择/显式更新 Agent 配置、查看实际执行配置、派生任务 |
| 消息 | 补充要求、显示待领取/已领取、修订或删除尚可修改的消息 |
| 完成 | 标记待验收、逐项验收、确认 Done、重新打开 |
| 生命周期 | Cancel、交付并清理 Worktree、Delete、恢复失败操作 |

保存任务成功、启动未确认时保留已创建的 Task ID，不返回空白新建表单。重试使用
原 command ID/创建 attempt，不重复创建 Task、Run 或 Worktree。

从列表进入详情保留列表上下文；从看板进入完整详情提供返回看板。Run 详情属于
任务详情内的二级导航，返回时保留所在 Run、筛选和滚动位置。

打开任务终端按 Task 所属项目定位。另一窗口已持有该 Surface/输入控制权时，
沿用 OwnedElsewhere 和控制权规则，不能用拖拽或切换页面抢占输入。

## 5. Agent 管理与配置

### 5.1 入口与作用域

Task 面板顶部提供全局 Agent 管理；任务页和新建/配置面板保留快捷入口。管理页共享当前
Runtime 数据根内的 Agent 库，便携版与注册版继续使用各自的数据根。

没有打开项目、没有 Task 时仍可管理 Agent；只有设置/清除项目默认值需要明确的
目标项目。未选择项目时保留全局编辑能力，并禁用默认设置按钮、提示先选择项目。

保留名称、简介、Codex 后端、模型、长期指令、预览、新建、保存、复制、重新
加载、归档/恢复、搜索/分页、显示已归档及设置/清除项目默认 Agent。

“设为默认”旁明确显示目标项目名。全部项目任务范围不会把它变成给所有项目
批量设置默认。已归档 Agent 恢复后不自动恢复旧默认关系。

### 5.2 生效语义

| 对象/操作 | 生效方式 |
| --- | --- |
| 项目默认 Agent | 新建草稿的默认选择，不改写现有 Task |
| 创建 Task | 固定所选 Agent ID/revision，事务校验版本及归档状态 |
| 修改公共 Agent | 追加配置 revision，既有 Task 继续使用固定上下文 |
| 显式更新某 Task 的配置 | 无活动/排队 Run 和未完成 intent 时追加 ExecutionContext；按已有规则切换会话 |
| 继续修改 | 使用 Task 当前固定的上下文，不自动读取公共 Agent 最新 revision |
| 重试历史 Run | 使用原 Run 引用的 ExecutionContext |
| 归档 Agent | 不再提供给新选择；清除相关默认；已固定配置的 Task 仍可继续/重试 |

保留“本次自定义”与保存的 Agent 配置的边界。修改本任务模型/指令时显式进入
自定义或配置更新流程，不发送互相冲突的 Agent 引用和原始覆盖字段。
名称不是身份；同名 Agent 使用短 ID、简介和版本消歧。

### 5.3 草稿与返回

导航上下文记录项目 ID、任务视图、选中 Task、草稿 ID、表单内容、模型覆盖、
验收条件、修改意见、消息草稿和返回位置。

进入 Agent 管理、刷新目录、预览配置和返回任务页都保留草稿。保存失败、版本
冲突或结果未知时保留输入与命令身份；未知结果先查询/重放，不用新 ID 再保存。
Agent 草稿以 profile ID 和基准版本管理；切换项目默认目标不覆盖正在编辑的全局
Agent 草稿。

## 6. 持久化、恢复与边界状态

- 项目无 Task、无终端时显示创建任务/打开终端入口，不创建占位 Run。
- Runtime 断开时保留最后快照并标记离线；执行和拖拽写操作不可假成功。草稿可继续
  编辑，重连后校验版本再提交。
- 停止期间完成、交付或另一窗口改状态：展示最终已提交状态，原拖拽操作报告冲突，
  不覆盖刚到达的交付结果。
- 删除中、归档中或尚未完成清理的任务显示具体操作阶段及重试入口。
- 旧项目目录缺失/有歧义时保留任务、历史和默认配置关联。已有有效冻结上下文的
  Task 可继续按原上下文执行；新 Task 必须补齐项目目录。
- 保存布局失败时不声称“可恢复”；保留视图并提供重试或明确的继续关闭选择。

## 7. 输入、响应式与可访问性

主目标为现有 Windows 桌面、中文、键盘与鼠标；沿用 Fluent/现有 Workspace
主题与资源字典。使用逻辑尺寸与系统文本缩放，不另引入 WebView UI。

- 宽窗口使用列表 + 详情 + 属性；不足空间时属性折叠到详情，任务列表沿用窄布局
  导航；看板优先保持可读列宽，可横向浏览。
- 网页原型在极窄宽度分行，只是预览适配；原生列顺序和键盘阅读顺序保持固定。
- 所有跨列动作有卡片菜单/状态菜单等价入口。键盘可移动焦点、打开卡片、选择状态；
  `Esc` 返回上一级或取消当前界面操作，不误发送给后台 Task。
- 只有任务终端获得焦点时，终端 Esc 才执行既有中断语义。
- `Ctrl+N` 继续新建 Workspace，普通新建标签命令继续在外层当前 Workspace 中操作。
  项目目录选择仅由 Task 面板的项目按钮触发；项目概览中的“打开终端”是显式项目动作。
- 状态用文字和图标同时表达；失败、等待输入、处理中通过可访问通知读出。
- 指针反馈目标 100 ms 内；异步操作立即给出待处理状态；动画使用现有控件并尊重
  减少动画设置，持续后台工作不遮挡整个界面。
